# Typische Fehler: Grundlagen & Begriffe

1. **„Firebird ist eine Datenbank.“** Das Produkt wird als Datenbank bezeichnet. → Ungenau, weil Firebird die Verwaltungssoftware ist, also das DBMS. Die Datenbank (Datenbasis) ist der damit verwaltete Bestand, beides zusammen das Datenbanksystem. Dass „Datenbank“ im Sprachgebrauch oft für das ganze System steht, ist verbreitet. Sobald es aber darum geht, wer Rechte prüft (das DBMS) oder was gesichert wird (die Datenbank), braucht man die genauen Begriffe. → Richtig: „Firebird ist ein DBMS. Die Vereinsdaten bilden die Datenbank, beides zusammen das Datenbanksystem.“
2. **Daten und Information gleichgesetzt.** „Die Datenbank speichert Informationen, also sind Daten und Information dasselbe.“ → Falsch, weil gespeicherte Zeichen erst durch Interpretation im Kontext zur Information werden. Dieselbe Zeichenfolge `17;2025;38` kann Verschiedenes bedeuten. → Richtig: Daten (dargestellte Information) → Information (interpretierte Daten) → Wissen (vernetzte Information, die beim Problemlösen hilft) an einem Beispiel zeigen.
3. **Persistent mit unveränderlich verwechselt.** „Der Pachtbetrag ändert sich jedes Jahr, also ist er transient.“ → Falsch, weil persistent nur heißt, dass Daten über das Programmende hinaus erhalten bleiben. → Richtig: transient sind nur Daten, die mit dem Programmlauf verschwinden (Variablen, ungespeicherte Eingaben). Ein jährlich geänderter, gespeicherter Wert ist persistent.
4. **Jede Redundanz als Fehler gewertet.** „Ein gutes Datenbanksystem speichert jeden Wert genau einmal, auch Backups sind Redundanz und daher schlecht.“ → Falsch, weil kontrollierte Redundanz einen bekannten Zweck und einen geregelten Umgang hat: Indexe und Replikate führt das System nach, ein Backup hält absichtlich den Stand eines Zeitpunkts fest. → Richtig: unkontrollierte Redundanz vermeiden, weil sie zu Inkonsistenz führt. Bei kontrollierter Redundanz Zweck und Umgang mit den Kopien benennen.
5. **Schema und Ausprägung vertauscht.** „Das Schema enthält alle Mitglieder“ oder „Ein `INSERT` ändert das Schema.“ → Falsch, weil das Schema nur die Struktur beschreibt (Tabellen, Spalten, Datentypen, Bedingungen) und sich durch DDL ändert. → Richtig: Ausprägung = konkrete Zeilen zu einem Zeitpunkt, geändert durch DML. Faustregel: Schema = Formularvordruck, Ausprägung = die ausgefüllten Formulare.
6. **Data Dictionary als separate Dokumentation verstanden.** „Das Data Dictionary ist die Word-Datei, in der die Tabellen beschrieben sind.“ → Für diesen Kurs zu kurz gegriffen, weil das Data Dictionary eines DBMS ein vom System selbst gepflegter Katalog ist. Er wird bei jeder DDL-Anweisung aktualisiert und vom DBMS bei jeder Anfrage genutzt (Rechte, Integrität, Optimierung). → Richtig: Data Dictionary = Systemkatalog mit Metadaten, in relationalen Systemen selbst als Tabellen abgelegt und per SQL abfragbar (Codds Regel 4).
7. **Inhalte der beiden Codd-Listen durcheinandergebracht.** „Codds zwölf Regeln sind Integration, Operationen, Katalog …“ oder „Regel 3 verlangt Transaktionen.“ → Ungenau, weil Codd zwei verschiedene Listen aufgestellt hat: neun Anforderungen, die beschreiben, welche Funktionen ein DBMS bereitstellen soll, und zwölf Regeln (gezählt 0 bis 12), die festlegen, wann ein System relational ist. Eine dritte, oft verwechselte Liste sind Codds zwölf OLAP-Regeln. → Richtig: bei einer Antwort sagen, welche Liste gemeint ist, und deren Einträge mit Inhalt nennen, z. B. „Anforderung Synchronisation: …“ oder „Regel 3, Behandlung von NULL: …“.
8. **Benutzerrollen mit Personen gleichgesetzt.** „Der Kassenwart ist Endnutzer, also kann er kein DBA sein.“ → Falsch, weil Rollen Tätigkeiten beschreiben. Eine Person kann mehrere Rollen haben, und eine Rolle kann von einer Gruppe ausgefüllt werden. → Richtig: Rolle über die Tätigkeit bestimmen, z. B. „Wenn der Kassenwart Sicherungen einrichtet und Rechte vergibt, handelt er als DBA.“
