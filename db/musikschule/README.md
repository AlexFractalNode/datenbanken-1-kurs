# Beispieldatenbank Musikschule

Eine kleine Musikschule: Personen sind Lehrkräfte oder Schülerinnen und Schüler, Kurse werden belegt, Termine finden in Räumen statt, Instrumente werden ausgeliehen, Lehrkräfte vertreten sich gegenseitig, Gebühren werden bezahlt (oder auch nicht). Alle Daten sind synthetisch und alle Personen erfunden.

| Datei | Inhalt |
| --- | --- |
| `schema.sql` | DDL in Firebird-3-Syntax (Referenz) |
| `schema.pg.sql` | dieselbe DDL für PostgreSQL / PGlite (nur `BLOB SUB_TYPE TEXT` → `TEXT`) |
| `seed.sql` | Daten, erzeugt mit `python db/musikschule/generate.py --seed 42`, läuft auf beiden Systemen |
| `generate.py` | Generator mit festen Namenslisten, deterministisch je Seed |
| `erd.dot` | ER-Diagramm in Chen-Notation (Graphviz) |

Ladereihenfolge: `schema.sql` (bzw. `schema.pg.sql`), danach `seed.sql`. Unterschiede zwischen Firebird und PostgreSQL stehen in [`../DIALECT-NOTES.md`](../DIALECT-NOTES.md).

## Namenskonventionen

- Tabellen und Spalten: deutsch, `snake_case`, ohne Umlaute (`ue`, `oe`, `ae`, `ss`). Die Daten selbst enthalten Umlaute.
- Primärschlüssel heißen `<tabelle>_id` und sind Identity-Spalten (`GENERATED BY DEFAULT AS IDENTITY`). Ausnahmen: `lehrkraft` und `schueler` (Schlüssel `person_id` = Fremdschlüssel auf `person`) und `belegung` (zusammengesetzter Schlüssel).
- Fremdschlüssel heißen wie die referenzierte Tabelle plus `_id` (`kurs_id`, `raum_id`). Rollen erhalten eigene Namen: `lehrkraft_id`/`vertreter_id`, `hauptinstrument_id`.

## Domänen

| Domäne | Typ | Regel |
| --- | --- | --- |
| `d_betrag` | `NUMERIC(8,2)` | `VALUE >= 0` |
| `d_niveau` | `VARCHAR(16)` | `'Anfaenger'`, `'Mittelstufe'` oder `'Fortgeschritten'` |

## Tabellen

### `person` (Supertyp)

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `person_id` | `INTEGER` | PK, Identity |
| `vorname` | `VARCHAR(30)` | NOT NULL |
| `nachname` | `VARCHAR(30)` | NOT NULL |
| `geburtsdatum` | `DATE` | optional |
| `email` | `VARCHAR(60)` | UNIQUE, optional |
| `telefon` | `VARCHAR(20)` | optional |
| `ort` | `VARCHAR(30)` | NOT NULL |

### `lehrkraft` (Subtyp von `person`)

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `person_id` | `INTEGER` | PK, FK → `person` ON DELETE CASCADE |
| `eingestellt_am` | `DATE` | NOT NULL |
| `stundensatz` | `d_betrag` | NOT NULL |
| `hauptinstrument_id` | `INTEGER` | FK → `instrument` ON DELETE SET NULL, optional |

### `schueler` (Subtyp von `person`)

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `person_id` | `INTEGER` | PK, FK → `person` ON DELETE CASCADE |
| `eintritt` | `DATE` | NOT NULL |
| `ermaessigt` | `BOOLEAN` | NOT NULL, Default `FALSE` |

Die Generalisierung ist **nicht disjunkt** (eine Person ist zugleich Lehrkraft und Schüler) und **partiell** (eine Person hat keine der beiden Rollen).

| `bezeichnung` | `VARCHAR(30)` | NOT NULL, UNIQUE |
| `familie` | `VARCHAR(20)` | NOT NULL, `'Tasten'`, `'Streich'`, `'Zupf'`, `'Blas'` oder `'Schlag'` |
| `leihgebuehr` | `d_betrag` | Monatsgebühr; NULL = nicht ausleihbar |

### `raum`

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `raum_id` | `INTEGER` | PK, Identity |
| `bezeichnung` | `VARCHAR(20)` | NOT NULL, UNIQUE |
| `etage` | `SMALLINT` | NOT NULL (Keller = -1) |
| `plaetze` | `SMALLINT` | NOT NULL, > 0 |
| `hat_klavier` | `BOOLEAN` | NOT NULL, Default `FALSE` |

### `kurs`

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `kurs_id` | `INTEGER` | PK, Identity |
| `titel` | `VARCHAR(60)` | NOT NULL |
| `instrument_id` | `INTEGER` | FK → `instrument` ON DELETE SET NULL; NULL bei Musiktheorie und Chor |
| `lehrkraft_id` | `INTEGER` | NOT NULL, FK → `lehrkraft` (`person_id`) |
| `raum_id` | `INTEGER` | FK → `raum` ON DELETE SET NULL; NULL = wechselnder Raum |
| `niveau` | `d_niveau` | NOT NULL |
| `max_teilnehmer` | `SMALLINT` | NOT NULL, > 0 |
| `gebuehr_monat` | `d_betrag` | NOT NULL |
| `startdatum` | `DATE` | NOT NULL |
| `enddatum` | `DATE` | optional, ≥ `startdatum` |
| `beschreibung` | `BLOB SUB_TYPE TEXT` (PG: `TEXT`) | optional |

### `belegung` (m:n `schueler` ↔ `kurs`)

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `schueler_id` | `INTEGER` | PK, FK → `schueler` (`person_id`) ON DELETE CASCADE |
| `kurs_id` | `INTEGER` | PK, FK → `kurs` ON DELETE CASCADE |
| `angemeldet_am` | `DATE` | NOT NULL |
| `abgemeldet_am` | `DATE` | optional, ≥ `angemeldet_am` |
| `rabatt_prozent` | `SMALLINT` | NOT NULL, Default 0, 0 bis 50 |

### `termin` (Unterrichtstermin)

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `termin_id` | `INTEGER` | PK, Identity |
| `kurs_id` | `INTEGER` | NOT NULL, FK → `kurs` ON DELETE CASCADE |
| `datum` | `DATE` | NOT NULL |
| `uhrzeit` | `TIME` | NOT NULL |
| `dauer_min` | `SMALLINT` | NOT NULL, > 0 |
| `raum_id` | `INTEGER` | FK → `raum` ON DELETE SET NULL; NULL = Raum des Kurses |
| `ausgefallen` | `BOOLEAN` | NOT NULL, Default `FALSE` |

UNIQUE (`kurs_id`, `datum`, `uhrzeit`).

### `ausleihe`

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `ausleihe_id` | `INTEGER` | PK, Identity |
| `instrument_id` | `INTEGER` | NOT NULL, FK → `instrument` |
| `schueler_id` | `INTEGER` | NOT NULL, FK → `schueler` (`person_id`) |
| `inventar_nr` | `CHAR(8)` | NOT NULL (Werte sind kürzer, daher mit Leerzeichen aufgefüllt) |
| `ausgabe` | `DATE` | NOT NULL |
| `rueckgabe` | `DATE` | NULL = noch ausgeliehen, sonst ≥ `ausgabe` |

### `vertretung` (rekursiv `lehrkraft` ↔ `lehrkraft`)

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `vertretung_id` | `INTEGER` | PK, Identity |
| `lehrkraft_id` | `INTEGER` | NOT NULL, FK → `lehrkraft` ON DELETE CASCADE (die vertretene Lehrkraft) |
| `vertreter_id` | `INTEGER` | NOT NULL, FK → `lehrkraft` ON DELETE CASCADE, ≠ `lehrkraft_id` |
| `von` | `DATE` | NOT NULL |
| `bis` | `DATE` | NOT NULL, ≥ `von` |
| `grund` | `VARCHAR(40)` | optional |

UNIQUE (`lehrkraft_id`, `vertreter_id`, `von`).

Dasselbe Paar kann sich mehrfach vertreten, in verschiedenen Zeiträumen. Das Paar allein ist deshalb kein Schlüssel. Der natürliche Schlüssel besteht aus (`lehrkraft_id`, `vertreter_id`, `von`) und ist als UNIQUE-Constraint abgesichert. Als Primärschlüssel dient trotzdem die Surrogat-ID `vertretung_id`. So bleibt die Tabelle bei der Konvention `<tabelle>_id`, Verweise und `UPDATE`/`DELETE` in Aufgaben brauchen nur eine Spalte, und eine Korrektur von `von` ändert keinen Schlüssel.

### `zahlung`

| Spalte | Typ | Bedingungen |
| --- | --- | --- |
| `zahlung_id` | `INTEGER` | PK, Identity |
| `schueler_id` | `INTEGER` | NOT NULL, FK → `schueler` (`person_id`) ON DELETE CASCADE |
| `kurs_id` | `INTEGER` | FK → `kurs` ON DELETE SET NULL |
| `ausleihe_id` | `INTEGER` | FK → `ausleihe` ON DELETE SET NULL |
| `betrag` | `d_betrag` | NOT NULL |
| `faellig_am` | `DATE` | NOT NULL |
| `bezahlt_am` | `DATE` | NULL = offen |
| `zahlungsart` | `VARCHAR(12)` | `'Ueberweisung'`, `'Lastschrift'` oder `'Bar'`; NULL solange offen |

Eine Zahlung gehört zu einem Kurs oder zu einer Ausleihe, nie zu beidem.

Fälle, auf die sich Aufgaben verlassen können:

- Personen 1–8 sind Lehrkräfte, 9–38 Schüler, Person 5 ist beides, Person 39 hat keine Rolle.
- Kurse 12 und 13 (Start Februar 2025) haben noch keine Belegung. Mehrere Kurse sind voll belegt.
- Kurse ohne Instrument (Musiktheorie, Chor) und ein Kurs ohne festen Raum (Musiktheorie).
- Instrument Ukulele wird weder unterrichtet noch ausgeliehen; Klavier und Schlagzeug sind nicht ausleihbar (`leihgebuehr` NULL).
- Offene Ausleihen (`rueckgabe` NULL), Abmeldungen (`abgemeldet_am`), ausgefallene Termine, offene Zahlungen (`bezahlt_am` NULL), Personen ohne Geburtsdatum, E-Mail oder Telefon.
- Die Vertretungen bilden eine Kette (Lehrkraft 1 wird von 2 vertreten, 2 von 3).
- Termine: acht Wochen ab 2. September 2024, ein fester Wochentag je Kurs.
- Telefonnummern beginnen mit `000` (keine echte Vorwahl), E-Mail-Adressen enden auf `@example.org`.
- Die Daten sind zeitlich stimmig, und `tests/test_db_load.py` prüft das:
  - Niemand meldet sich zu einem Kurs an oder leiht ein Instrument aus, bevor er oder sie in die Schule eingetreten ist.
  - Kursgebühren werden frühestens mit der Anmeldung fällig und bezahlt, nach einer Abmeldung wird nichts mehr fällig.
  - Leihgebühren entstehen frühestens mit der Ausgabe.
  - Termine liegen innerhalb der Kurslaufzeit.

Neu erzeugen: `python db/musikschule/generate.py --seed 42` (schreibt `seed.sql`). Andere Seeds ergeben andere Daten; die Aufgaben beziehen sich auf Seed 42.
